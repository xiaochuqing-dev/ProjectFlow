# ProjectFlow 自动化项目档案管理 PRD

日期：2026-06-21

## 背景

当前 ProjectFlow 已经能导入项目、生成项目画像、刷新 Git evidence、生成候选变更、进入变更审查、沉淀项目档案，并把部分长期数据拆到独立页面。但从实际使用看，流程仍有三个核心问题：

1. 长期资源不好管理：成长时间线、字段来源链、待确认档案、档案变化、分析记录等入口已经存在，但详情页缺少日期分组、长条卡片、二级详情和快速筛选。数据多到 3 个月后，用户需要翻找，管理成本会快速上升。
2. 首页存在重复表达：今日变化闭环和最近活动展示了高度相似的候选变更、文件变化和跳转动作，占用空间且削弱重点。
3. 审查页偏人工写入：结构化变更详情和项目档案页仍以大文本框为中心，像让用户手动写档案，而不是让系统先自动总结，用户只做审查、采纳、修正。

这会让 ProjectFlow 从“自动管理项目成长过程”退化成“很多表单和列表”。本轮改进的目标是把核心体验重新拉回：自动生成候选事实，用户审查确认，确认后的事实进入长期档案、每日回顾和成果输出。

## 目标

- 让长期项目资源可管理：所有长期资源页面都按时间、类型、状态组织，列表项能点进完整详情。
- 让首页只承担工作台职责：显示当前项目的下一步动作和最关键状态，不重复展示同一批变更。
- 让审查流程自动化优先：系统先给出摘要、影响、证据、建议沉淀字段，用户默认只需采纳或驳回。
- 让项目档案成为确认后的资产库：档案字段显示当前值、来源、更新时间和候选建议，而不是默认让用户手写大段文本。
- 让每日回顾、README、周报等输出能明确复用已确认档案、成长记录和变更证据。

## 非目标

- 不重做整体 UI 视觉风格。
- 不把 ProjectFlow 改成通用文档系统、知识库或 Kanban。
- 不取消人工编辑能力；人工编辑只作为修正入口，不作为主流程。
- 不要求引入新的 AI 供应商或复杂模型编排。本轮可以先用现有模型能力和本地规则生成候选摘要。

## 用户验收标准

一个新用户不看文档，也不需要 Agent 解释，可以独立完成：

导入项目 -> 看到画像 -> 绑定路径 -> 开发一天 -> 回来看变化 -> 审查 -> 生成输出。

本轮新增验收标准：

- 用户进入成长时间线、字段来源链、档案变化、分析记录等页面后，能按月份、日期、类型快速定位旧记录。
- 用户看到列表项时，先看到日期、状态、摘要、来源和关键影响，再点进详情，而不是直接面对长文本。
- 用户在结构化变更详情页不输入任何文字，也能完成一次合理的采纳或驳回。
- 用户需要修改时，人工编辑入口明确是“修正 AI 总结”，不是空白表单。
- 首页同一条候选变更不应同时以完整卡片形式出现在两个主区域。
- 输出页面能说明使用了哪些已确认来源，而不是只显示“已连接/有几条”。

## 核心设计原则

1. 先时间后详情：长期资源先按月、日、类型聚合，再进入长条卡片和完整详情。
2. 先候选后确认：模型或本地规则生成候选事实，用户审查，确认后写入项目档案。
3. 先摘要后原文：列表只展示可决策摘要，原始证据和长文本放进详情页。
4. 一个事实一个主入口：同一批变更不要在首页多处重复完整展示。
5. 人工输入降级：大文本框默认隐藏到修正区，主界面展示系统生成结果和采纳动作。

## 信息架构

### 首页工作台

首页只展示：

- 当前项目
- 下一步动作
- 今日变化闭环摘要
- 项目画像摘要
- 关键计数入口

首页不再完整重复：

- 最近活动里的候选变更全文
- 与今日变化闭环相同的文件变化列表
- 项目档案入口页已经存在的长文本内容

### 长期资源中心

每类长期资源都采用统一结构：

- 顶部筛选：月份、类型、状态、来源、关键词
- 时间分组：按月 -> 按日
- 长条卡片：日期、标题、来源、状态、摘要、关键数量
- 详情入口：进入完整记录页或详情抽屉
- 返回路径：回到来源列表，并保留筛选条件

覆盖范围：

- 成长时间线
- 字段来源链
- 待确认档案
- 档案变化
- 分析记录
- 每日回顾来源
- 结构化变更
- Git evidence / Evidence Bundle

### 自动化审查页

结构化变更详情页应从“人工填写表单”改成“审查台”：

- 顶部：自动生成的结论、日期、来源、状态、影响级别
- 中部：变更摘要、涉及模块、文件、风险、测试证据
- 下部：建议写入项目档案的候选字段
- 操作：采纳、驳回、标记待确认、手动修正
- 手动修正：折叠区，仅在用户需要改 AI 总结时展开

## 成功指标

- 90 天模拟数据下，任意一条旧成长记录可在进入对应页面后 2 次点击内定位到日期分组。
- 首页重复候选变更卡片数量为 0。
- 结构化变更详情页默认可见的文本框数量不超过 1 个，且必须有明确“修正”语义。
- 采纳一条候选变更后，项目档案、字段来源链、档案变化、每日回顾来源至少有一处可追溯更新。
- 输出页能展示本次输出引用的确认来源清单，并可跳转查看来源详情。

## 阶段

- 阶段 1：资源管理信息架构与数据字段统一
- 阶段 2：长期资源日期分组与详情卡片
- 阶段 3：首页去重与工作台主线压缩
- 阶段 4：结构化变更自动化审查页
- 阶段 5：项目档案从手写页改为审查工作台
- 阶段 6：输出链路、回归验证与新用户验收
