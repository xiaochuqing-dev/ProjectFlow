# 阶段 4：结构化变更自动化审查页

## 目标

把结构化变更详情页从“人工填表”改成“AI/规则候选审查台”。用户应主要审查系统总结，而不是从空白文本框开始写。

## 当前问题

页面存在大量可编辑 textarea：

- 基本判断
- 完整证据
- 验证与风险
- 沉淀到项目档案

这种布局让用户感觉自己在写报告，不是在审查项目事实。

## 新页面结构

### 顶部结论

- 标题
- 日期时间
- 来源类型
- 状态
- 置信度
- 影响级别
- 主操作：采纳、驳回、待确认

### 自动摘要

展示系统生成的内容：

- 这次改了什么
- 影响了哪些模块
- 为什么重要
- 可能风险
- 是否有测试或构建证据

摘要可以由模型生成；模型不可用时，用文件路径、Git diff 统计和已有 Evidence Bundle 规则生成本地摘要。

### 证据卡片

把证据拆成可点卡片：

- 文件变化
- 提交或工作区来源
- 测试证据
- 构建证据
- 相关任务

每张卡片点开后看完整内容。

### 档案候选

系统自动给出建议沉淀内容：

- 能力
- 风险
- 技术决策
- 经验沉淀
- 成果素材
- 下一步目标

用户可以逐项采纳，不需要一次性采纳整段文本。

### 手动修正

手动编辑区默认折叠，入口文案为：

修正 AI 总结

展开后才显示编辑框。

## 验收

- 用户不输入文字，也可以完成一次采纳或驳回。
- 默认首屏看不到大面积空白 textarea。
- 每个候选档案字段都能看到来源证据。
- 采纳后能跳转到档案变化或字段来源链查看结果。
