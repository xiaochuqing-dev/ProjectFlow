# ProjectFlow V3.3.2 总计划

> 原始文档来源：`docs/superpowers/plans/2026-07-07-projectflow-v3-3-2.md`
> 设计文档来源：`docs/superpowers/specs/2026-07-07-projectflow-v3-3-2-design.md`

目标：让变更分析变得具体、稳定、可解释、感知 GitHub，并能产出结构化的项目能力卡片。

架构：扩展现有的 scan、segment、sediment、analysis-job 和 API 边界。持久化诊断信息和能力卡片为结构化实体；GitHub 保持可选，模型输出由后端规则验证。

技术栈：Java 17 / Spring Boot / JPA，PostgreSQL / H2，TypeScript / React / Next.js，本地 Git + 可选 GitHub CLI。

---

## 分析管线

本地 Git 和 Agent 结果是权威证据来源。一次扫描抓取提交/文件/差异提示、工作区状态、GitHub 元数据、耗时和确定性指纹。规则构建受证据约束的兜底分段；配置的模型可将其改写为固定 schema。证据验证和质量门禁拒绝凭空捏造或目录级摘要。模型输出失败则重试一次，仍失败则显式降级；兜底输出不充分则标记为需人工整理。

指纹不变时复用已有的批次和分段。GitHub CLI 与远程检查使用只读短命令。CLI 缺失、未登录、无 upstream、无权限、代理或网络不通均不阻塞本地分析。

## 能力卡片流程

能力分析基于已确认沉淀、开发推进段、证据引用、提交链接、分析记录和 Agent 结果，一次生成 3 到 8 张结构化候选卡片。每张卡片有独立状态和证据，确认一张不影响其他。旧版 ProjectMemory 字符串仅作为可折叠的兼容档案展示。

## 沉淀审核与证据

列表和详情路由使用 V3.3 确认端点，支持 NEW_SEDIMENT、MERGE_EXISTING、EVIDENCE_ONLY、IGNORE 四种动作。建议策略根据已有沉淀相似度和证据类型推断保守动作。批量创建从主路径中移除。证据视图分离摘要变更、Git 证据、验证证据和来源材料。

## 验证

后端测试覆盖质量拒绝、降级诊断、指纹复用、GitHub 降级、建议推断、结构化能力确认和四动作审核。前端验证使用 TypeScript / Next 生产构建。完整 Maven 测试和启动脚本/文档检查完成发布门禁。
