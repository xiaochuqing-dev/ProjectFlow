ProjectFlow 开源与个人使用产品逻辑审查报告

审查日期：2026 年 7 月 10 日

一、当前产品判断

ProjectFlow 最有价值的部分已经不是任务管理，而是把本地 Git、Agent result 和用户确认串成“待整理变更、开发推进段、建议沉淀、项目沉淀”的证据闭环。这个方向适合 AI 辅助开发中的个人开发者，也比通用看板更有辨识度。

目前最大产品问题是接入、概念和发布方式仍偏工程内部使用。新用户需要理解 zip、真实路径、GitHub、模型、Agent 协议、工作会话、证据包、项目变更、沉淀和能力卡片，首次使用成本过高。

二、开源准备现状

GitHub 仓库当前已经是 PUBLIC，但没有 LICENSE。公开可见不等于获得开源使用、修改和分发授权，因此现在还不能算完整的开源项目。

仓库缺少 CONTRIBUTING、SECURITY、CHANGELOG、行为准则、Issue 模板、Pull Request 模板、GitHub Actions、版本标签和 Release。master 分支也没有保护规则。

GitHub 描述仍把项目称为“项目管理和 AI 复盘平台”，与当前本地优先的开发变更理解工具定位不一致；topics、主页和 Release 均为空。

三、个人使用产品逻辑的优先优化

1. 把本地项目路径改成默认主入口，zip 只做补充入口

现在用户先导入 zip 获取项目画像，又绑定真实目录获取 Git 变化。同一份源码有两份来源，zip 很快过期，用户也难理解为什么已经绑定目录还必须重新压缩上传。

建议：个人本地模式选择项目文件夹后，自动完成安全目录扫描、Git 检查和基础画像；zip 仅用于无法绑定目录、跨设备导入或只读样本。这样可以直接消除最明显的数据重复和过期问题。

2. 做一个真正的首次运行向导

第一屏只回答四件事：选择项目文件夹、确认 Git 状态、选择是否配置模型、完成第一次变化扫描。GitHub 和 Agent 协议在需要时再引导，不要一开始同时展示所有高级入口。

每一步都要区分成功、具体失败原因、输入异常、登录差异和重复操作限制，并提供下一步按钮。

3. 界面只保留四个用户概念

主界面保持“待整理变更、开发推进段、建议沉淀、项目沉淀”。WorkSession、EvidenceBundle、ProjectChange、AnalysisJob 等兼容或技术实体放入证据详情和高级视图，不再让普通用户先理解数据库对象。

4. 明确模型的作用和费用边界

本地规则负责事实，模型负责解释，用户负责确认，这个原则正确。产品上还需要在每次调用前显示发送的数据范围、预计输入规模、所用模型、是否可能产生费用；完成后显示模型是否参与、失败原因和实际结果来源。

建议增加“模型发送预览”和“永不发送的路径”说明，强化本地优先项目的信任感。

5. 增加可恢复的备份、导入和升级路径

当前有 H2 数据导出脚本，但缺少界面内恢复、备份清单、数据版本和升级前自动备份。个人用户最在意的是项目沉淀不能因为升级丢失。

建议提供一键导出和一键恢复，导出内容包含数据库、确认沉淀、模型配置的非密钥部分和版本信息；升级前自动备份，并明确密钥不进入备份。

6. 区分个人模式和团队模式

个人模式应默认只监听 127.0.0.1，可选免注册或首次创建本地账户，不要求 PostgreSQL、Redis、Docker。团队模式再启用多用户、完整认证、外部数据库、访问控制和部署文档。

不要让个人用户承担团队部署复杂度，也不要把个人模式的安全假设直接带到公网。

7. 降低安装门槛

当前 Windows 启动脚本仍要求用户预装 Java、Maven、Node 和 npm，并在本机执行构建。Docker 模式也不是完整应用镜像，只负责数据库并继续调用本地构建工具。

建议发布可下载版本，至少提供 Windows 打包包和完整 Docker Compose 镜像；随后再补 macOS 和 Linux。Release 中附带版本、数据升级说明、校验值和已知问题。

四、开源发布前必须完成

1. 选择并加入明确许可证。若希望广泛使用和贡献，可评估 Apache-2.0 或 MIT；涉及专利授权偏好时优先评估 Apache-2.0。

2. 更新 GitHub 描述、README 首屏、topics 和截图，使定位统一为本地优先的 AI 辅助开发变更理解与项目沉淀工具。

3. 加入最小贡献与安全文档，明确如何报告本地路径、模型密钥和命令执行相关漏洞。

4. 建立 CI，所有发布必须保证前端构建、前端测试、后端测试和依赖审计通过。

5. 创建首个版本标签和 Release，不要让用户直接从持续变化的 master 安装。

五、建议的三个版本目标

内测版：修复能力任务缺陷，全部测试通过，本地路径可完成首次扫描，备份可恢复。

开源预览版：许可证、贡献文档、CI、完整安装方式、统一产品定位、隐私说明齐全。

稳定版：本地路径取代 zip 成为主入口，数据库迁移可验证，Windows 发布包和完整 Docker 镜像可用。

六、暂未验证事项

本次没有实际使用新用户身份走完注册、导入、绑定、模型配置、分析、确认和导出全流程。

没有测试 macOS、Linux、反向代理和公网团队部署。

没有使用真实 DeepSeek Key 验证长任务费用、超时和结果质量。
