# 首页变化扫描持久化任务设计

## 目标

修复首页“分析新变化”在刷新页面、离开首页后丢失运行状态和结果的问题，并确保模型归并耗时或失败时任务最终进入成功或失败状态，不再无限转圈。

## 方案

复用现有 `ProjectAnalysisJob` 后台任务机制，不新增独立任务系统：

- 增加 `WORK_SESSION_SCAN` 任务类型和对应的 `WorkSessionScanResponse` 持久化结果。
- 增加异步变化扫描入口；保留现有同步扫描接口，避免破坏已有调用方。
- `ProjectAnalysisJobRunner` 在后台调用现有 `WorkSessionScanService.scan`，把完整扫描结果或错误写入任务记录。
- 现有任务列表和单任务查询接口返回变化扫描结果；应用重启时继续恢复 `QUEUED`、`RUNNING` 任务。
- 首页通过现有任务 hook 提交并轮询变化扫描任务。页面重新加载或路由返回时，从后端任务列表恢复活动状态和最近成功结果。
- 任务成功后刷新项目上下文，使待确认变更等派生数据同步更新。

## 数据流

1. 用户点击“分析新变化”。
2. 前端创建 `WORK_SESSION_SCAN` 任务，接口立即返回任务记录。
3. 后端异步读取 Git 证据、执行规则归并，并在配置模型时尝试模型增强。
4. 前端轮询任务状态；刷新或离页不会取消后端任务。
5. 用户再次进入首页时，任务列表恢复 `QUEUED` / `RUNNING` 状态。
6. 任务完成后，首页展示持久化扫描结果并刷新项目上下文。

## 错误与边界

- 同一项目同一时间只复用一个活动的变化扫描任务，避免重复扫描和重复写入。
- 模型调用沿用现有超时和本地规则回退；回退成功时任务为 `SUCCEEDED`，并在扫描警告中说明。
- 真实扫描异常写入任务 `FAILED` 和安全错误消息，首页停止转圈并显示错误。
- 任务读取继续执行用户和项目所有权校验。
- 不在浏览器存储访问令牌、扫描结果或新的持久化副本。

## 验证

- 后端回归测试先证明：异步扫描接口立即返回任务，任务可通过列表/详情恢复，最终结果被持久化。
- 覆盖活动任务去重和无权限访问。
- 前端构建验证任务类型、结果恢复和页面接线。
- 后端执行相关测试及完整测试集。
