# V3.3.6 Migration and Compatibility

V3.3.6 uses the existing Hibernate update strategy and does not require clearing H2 or PostgreSQL data.

New review metadata is nullable. Old project changes remain source-unknown instead of being assigned to a new batch. Old project sediments keep their content and are considered pending capability analysis until a successful run records otherwise. Old capability cards without an analysis job remain labelled as legacy source-unknown cards.

Existing confirmed sediments, confirmed capability cards, Provider rows, and the current default Provider are not deleted or rewritten. Legacy ellipsis-ended content remains marked as truncated; migration never fabricates missing text.

If schema update fails, the original database remains the recovery source. Preserve `.projectflow/local-data/` for embedded H2 and the PostgreSQL volume before retrying an environment-level migration.
