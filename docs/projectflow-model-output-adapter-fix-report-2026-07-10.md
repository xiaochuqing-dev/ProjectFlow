# ProjectFlow 模型输出适配与任务容错修复报告

日期：2026-07-10

## 目标

解决模型已经返回内容，但因 JSON 格式、字段别名、卡片数量或证据引用问题被误判为整体失败的问题；同时拆分能力分析长事务，减少重复提示并区分失败阶段。

## 设计方案

统一适配链路为：模型原始内容 → JSON 提取与轻量修复 → 外层和字段别名归一化 → 单项校验与去重 → S 编号映射真实证据 → 中文内容清洗 → 短事务原子保存。

能力分析事务拆为三段：短事务读取项目、确认推进段和模型配置；无事务等待模型并处理输出；短事务替换未确认候选并保存任务结果。模型或后处理失败时不会提前删除旧候选。

## 已完成变更

1. 新增 ModelOutputAdapter，支持严格 JSON、Markdown JSON 代码块、前后解释文字、直接数组、单对象、外层多包一层、capabilities/capabilityCards/cards 等别名和尾逗号修复。
2. 能力分析和开发推进段共用适配器。模型输入使用 S1、S2 等来源编号，后端恢复 segment、atom 和 evidenceRefs。
3. 能力卡片逐项处理：缺少非核心字段时保守补全；无效项单独丢弃；重复项去重；超过 8 项截断；少于 3 项仍成功但给出警告；无证据项保存为需补证据。
4. 新增 SUCCEEDED_WITH_WARNINGS。任务结果记录有效卡片数、需补证据数、是否修复 JSON、识别和丢弃项数、无效来源编号数。
5. 失败阶段区分模型请求、模型返回解析、输出归一化、单项校验、证据绑定、内容清洗和数据库保存。用户可见提示不再把返回后处理失败写成模型调用失败。
6. 能力分析不再持有长数据库事务。旧候选只在新结果可保存时原子替换，已确认能力不删除。
7. 能力页集中显示完整警告，技术诊断放入“分析详情”；轮询临时失败自动重试，连续三次失败才提示本地服务连接问题。

## 验证结果

后端完整测试通过：147 项测试全部成功。定向覆盖 ModelOutputAdapterTest、ModelSegmentEnricherTest、ProjectCapabilityServiceTest、ProjectAnalysisJobServiceTest。

前端生产构建通过：Next.js 编译、TypeScript 检查和 20 个页面静态生成均成功。

## 风险与边界

没有使用真实模型 API Key 做网络联调。来源缺失时当前采用保守策略标记需补证据，不进行高风险语义猜测。模型原始返回只记录是否存在，不在前端展示原始 JSON 或异常栈。
