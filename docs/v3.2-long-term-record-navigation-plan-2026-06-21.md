# ProjectFlow V3.2 长期记录导航改进计划

> 日期：2026-06-21  
> 范围：每日回顾来源、项目画像右侧信息、成长时间线、字段来源链、待确认档案、档案变化、Git evidence 明细  
> 核心验收：新用户不读文档，也能独立完成“导入项目 -> 看到画像 -> 绑定路径 -> 开发一天 -> 回来看变化 -> 审查 -> 生成输出”。

## 1. 当前问题

### 1.1 信息被挤在摘要页

`/project-intelligence` 右侧栏目前直接塞入：

- 分析记录
- 确认原则
- 成长时间线
- 字段来源链
- 待确认档案
- 最近档案变化

这些内容都属于长期累积数据。项目运行几周后，条目会快速增长，摘要页会变成拥挤列表，用户很难判断“当前应该做什么”。

### 1.2 数量和有无状态重复

每日回顾来源已经展示数量，却仍显示“有 / 无”。这会制造表述噪音。数量本身已经说明状态，卡片应该变成可点击入口，而不是再叠一层状态标签。

### 1.3 来源链没有形成可追溯页面

字段来源链、档案变化、待确认档案都在表达同一个核心问题：

“项目档案为什么变成现在这样？”

但现在它们分散在右侧卡片里，没有一个能承载完整历史、筛选、时间线和详情的页面。

### 1.4 Git evidence 明细不足

用户点进 Git 证据页面后，仍然只能知道“发生了变化”，但不知道变化大概改了哪些模块、文件、能力、风险或输出素材。这会削弱证据包到候选变更的可信度。

## 2. 设计原则

### 2.1 摘要页只回答三个问题

工作台、每日回顾、项目画像首页只保留：

- 当前状态是什么？
- 有多少条需要看？
- 下一步去哪处理？

不在摘要页展示完整历史。

### 2.2 每一个数量都必须可点击

只要 UI 显示 `3 条`、`14 个`、`待确认 4 条`，就必须能进入对应明细页。不能只展示数字却没有去处。

### 2.3 长期数据进入专页

以下内容必须用专页承载：

- 每日回顾来源
- 成长时间线
- 字段来源链
- 待确认档案
- 档案变化
- Git evidence 明细

摘要页最多展示最近 1 到 3 条和入口按钮。

### 2.4 空状态要短

空状态只展示：

- 当前没有什么
- 为什么没有
- 下一步做什么

不生成长模板，不输出 Markdown 段落。

## 3. 目标信息架构

### 3.1 工作台

保留主流程，不重复塞入口：

```text
项目选择 / 添加项目
当前项目状态
主流程下一步
最近活动摘要
```

工作台里的“最近活动”只展示最近 5 条，更多进入活动页。

### 3.2 每日回顾

`/dev-logs` 保留草稿编辑能力和来源摘要。

来源摘要卡片改成：

```text
当日日志        2 条    查看
项目演进        1 条    查看
任务证据        3 个    查看
风险与决策      0 条    查看
```

不再展示“有 / 无”。

新增页面：

```text
/dev-logs/sources?projectId=xxx&date=2026-06-21
```

页面结构：

- 顶部：项目、日期、来源总数
- 分组：当日日志、项目演进、任务证据、风险与决策
- 每组：列表 + 详情抽屉或详情卡
- 空组：短句说明，无长模板

### 3.3 项目画像

`/project-intelligence` 保留：

- 项目档案编辑
- 分析入口
- 少量右侧入口卡片

右侧栏改成入口集合：

```text
成长时间线      18 条    查看
字段来源链      9 项     查看
待确认档案      4 条     审查
档案变化        12 条    查看
分析记录        6 条     查看
```

不直接在右侧栏展示完整列表。

### 3.4 成长时间线页面

新增：

```text
/project-intelligence/timeline?projectId=xxx
```

页面目标：让用户看到项目长期演进，而不是只看到最近几条。

结构：

- 按月份或日期分组
- 支持类型筛选：采纳变更、证据包、每日回顾、手动档案
- 每条展示：时间、标题、来源、影响字段、简短变化
- 点击后展开：详细变化、关联证据、可用于输出的摘要

### 3.5 字段来源链页面

新增：

```text
/project-intelligence/fact-sources?projectId=xxx
```

页面目标：解释每个档案字段为什么可信。

结构：

- 左侧字段列表：项目定位、当前阶段、已完成能力、风险、技术决策等
- 右侧来源链：当前值、来源类型、是否用户确认、最近更新时间
- 支持查看历史来源，不只看最新来源
- 可从来源跳转到候选变更、每日回顾或证据包

### 3.6 待确认档案页面

新增或复用变更审查入口：

```text
/tasks?type=project-memory
```

页面目标：让用户处理“哪些档案候选还没确认”。

结构：

- 待确认字段
- 建议内容
- 来源
- 采纳 / 忽略
- 采纳后写入字段来源链和成长时间线

### 3.7 档案变化页面

新增：

```text
/project-intelligence/changes?projectId=xxx
```

页面目标：展示项目档案每次变化了什么。

结构：

- 时间线
- 变化字段
- 旧内容摘要
- 新内容摘要
- 来源：手动保存 / 采纳变更 / zip 分析 / Agent Result / Evidence Bundle

### 3.8 Git Evidence 明细页

现有工作会话详情页继续保留，但增强表达：

- 变化摘要用中文，不只显示 commit 或行数
- 展示主要变更区域：前端、后端、文档、配置、测试
- 展示新增、修改、删除的大概内容
- 列出关键文件，长路径压缩但可完整查看
- 保留返回按钮

## 4. 需要检查并调整的其他区域

### 4.1 成果输出

生成依据区域只展示来源统计和可用性，不展示长文本堆叠：

- 项目档案 1 份
- 成长记录 18 条
- 每日回顾 6 条
- 任务证据 12 条

每个数字进入明细来源页。

### 4.2 最近活动

工作台最近活动不能无限增长。首页只展示最近 5 条，更多进入：

```text
/activity?projectId=xxx
```

如果暂时不新增页面，至少提供“查看更多”入口到已有的变更审查或工作会话详情。

### 4.3 项目材料

项目材料数量会增长。摘要页只展示：

- 材料总数
- 最近导入
- 当前有效画像来源

完整材料列表保留在项目文件或材料详情页。

### 4.4 分析记录

分析记录当前在项目画像右侧栏展示列表。后续应转为：

- 首页显示数量和最近一次
- 完整列表进入分析记录页
- 文件分析和项目分析分组

## 5. 阶段计划

### 阶段 1：页面边界梳理

目标：确定哪些内容留在摘要页，哪些进入专页。

任务：

- 梳理 `/dashboard`、`/dev-logs`、`/project-intelligence`、`/ai-review` 的重复入口。
- 定义摘要卡字段：标题、数量、简短说明、目标路由。
- 删除摘要页中的长列表展示规则。

验收：

- 任意摘要卡最多展示 3 条预览。
- 任意数量都能点击进入明细。
- 首页和右侧栏不承载完整历史。

### 阶段 2：每日回顾来源专页

目标：让每日回顾来源从“模板文本”变成“可查证来源”。

任务：

- 新增每日回顾来源页。
- 来源卡移除“有 / 无”，保留数量和查看入口。
- 明细页按来源类型分组展示真实记录。

验收：

- 用户能从每日回顾页 1 次点击看到当日具体来源。
- 没有来源时只显示短空状态。
- 保存每日回顾前，用户能确认草稿来自哪些真实记录。

### 阶段 3：项目画像长期记录专页

目标：把右侧栏从“历史堆叠区”改成“导航入口区”。

任务：

- 新增成长时间线页。
- 新增字段来源链页。
- 新增档案变化页。
- 待确认档案跳转到变更审查并带筛选。
- 项目画像右侧栏只保留入口卡和数量。

验收：

- 项目画像右侧栏在 6 个月数据量下仍不溢出。
- 成长时间线能按日期查看历史。
- 字段来源链能解释每个项目档案字段的来源。

### 阶段 4：Git Evidence 明细增强

目标：用户点进证据后能知道“大概改了什么”。

任务：

- 工作会话详情页增加中文变化摘要。
- 按文件角色聚合：前端、后端、文档、配置、测试、其他。
- 新增“新增 / 修改 / 删除”概览。
- 长路径支持完整查看，不挤压布局。

验收：

- 用户不看 git diff，也能知道这轮开发的主要变化。
- 证据包生成候选变更前，页面能解释候选从哪里来。

### 阶段 5：输出来源打通

目标：周报、README、简历素材不再像模板生成，而是能追溯来源。

任务：

- 成果输出页来源卡改成可点击入口。
- 输出草稿旁展示所用来源：项目档案、成长记录、每日回顾、任务证据。
- 缺少来源时提示补齐路径，而不是生成空泛模板。

验收：

- 用户能知道输出草稿用了哪些已确认资料。
- 没有确认来源时，页面明确告诉用户应该先审查或保存什么。

## 6. 最终验收标准

### 独立上手验收

一个新用户不读文档、不需要 Agent 解释，能独立完成：

```text
导入项目 -> 看到画像 -> 绑定路径 -> 开发一天 -> 回来看变化 -> 审查 -> 生成输出
```

### 长期使用验收

一个项目持续使用 6 个月后：

- 工作台仍然只展示当前下一步和最近活动。
- 每日回顾页不会被历史记录撑爆。
- 项目画像右侧栏仍然是入口，不是历史堆叠。
- 成长记录、字段来源、档案变化都有专页可查。
- 每个输出都能追溯到已确认来源。

### 文案验收

- 不用“有 / 无”重复表达数量。
- 不用长 Markdown 模板占据信息区。
- 空状态不超过两句话。
- 所有可点击元素必须有明确 hover / active 状态。
- 不可点击状态只能是信息徽标，不做成按钮。
