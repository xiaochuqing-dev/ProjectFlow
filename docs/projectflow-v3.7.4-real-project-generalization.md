# ProjectFlow V3.7.4 Real-project Generalization

## Boundary

The claim is bounded to the committed Calibration, frozen Holdout, original V3.7.3 regression set and product-chain E2E. It is not a universal accuracy claim. Production and evaluation use the same `ProjectUnderstandingPromptBuilder`, Model Gateway, Evidence allow-list, capability registry and view registry.

## Sets

Calibration contains 21 cases. It covers frontend, backend, fullstack, CLI, script collection, notebook/data material, desktop, monorepo, infrastructure, research documents, Agent-driven material, legacy, unfinished, no-Git, chaotic mixed material, long code, conflicting documents, authorized portfolio context, stale README, large-file tail revision and an important extensionless file.

Holdout contains eight separately identified cases: a normal Go service, mobile product documents, an 80,020-line tail revision, an extensionless important document, conflicting Agent/CI evidence, an unknowable historical reason, YAML operations material and authorized portfolio isolation.

Before any formal Holdout run, a static contract test found that several human labels used category names not present in the production atomic shape/view vocabulary. They were mapped to existing production labels before freeze and before any Holdout result was observed. A pre-formal GLM diagnostic also showed that some cases supplied complete source facts while still marking a deep-read tool as required. Those fixtures were corrected so source content is separate and a tool is expected only when intake explicitly leaves an information gap. No prompt rule, case ID, path or expected answer was added. Permanent dataset-contract tests now prevent vocabulary drift, missing capability fixtures and “fully supplied but still must read” contradictions.

## Auditable interpretation

Critical Evidence recall counts required source IDs found by a successful structured run. Selection specificity is reported separately and does not classify additional valid allow-listed Evidence as invalid. Invalid Evidence is any reference outside the current case allow-list and must remain zero.

Unsupported Strong Fact means a factual claim without Evidence that is neither UNKNOWN nor INFERRED. Promotion safety, declared/verified separation, historical reason, deprecation, technical-debt and Agent Result boundaries are also enforced by deterministic tests because a model-only aggregate cannot prove persistence behavior.

Large-file middle/tail recall uses generated raw fixtures with committed hashes and exact expected line locations. Unread disclosure is based on explicit range coverage, not a model statement that the whole file was read.

Multi-project and multi-Agent results use authenticated ownership checks, persisted facts, candidate writes and Context Packages. They do not infer authorization from model output.

## Formal result

Formal Calibration, Regression, Holdout and product E2E values are recorded in the model evaluation, Holdout and final acceptance reports. Initial diagnostic runs remain archived and are not substituted for formal results.
