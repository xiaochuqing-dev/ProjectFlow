# V3.2 工作台交互与信息去重改进计划

日期：2026-06-21

## 目标

让新用户不看文档也能独立完成：

导入项目 -> 看到画像 -> 绑定路径 -> 开发一天 -> 回来看变化 -> 审查 -> 生成输出

本计划只处理当前页面表达和交互清晰度，不改变核心数据模型。

## 当前问题

1. 最近活动列表的重点不够突出，待审查、今日候选、已采纳记录混在一起，用户难以判断下一步该点哪里。
2. 部分入口重复出现：首页已有入口，其他区域又展示同一跳转或同一数据，造成空间浪费和认知噪音。
3. 有些元素看起来像按钮但不能点击，用户会误以为功能失效。
4. 每日回顾来源仍偏模板化，长段 Markdown 式文本会让用户看不清真实来源状态。

## 设计原则

1. 首页只保留“下一步主动作”和少数关键入口。
2. 可点击元素必须有明确 hover、active、cursor、aria 反馈。
3. 不可点击内容改成信息气泡或状态标签，不使用按钮尺寸。
4. 详情信息放到详情页或弹窗，不在首页重复铺开。
5. 输出来源按“有 / 无 / 需要补充”展示，不直接堆长模板。

## 阶段 1：最近活动重构

目标：让“刷新变化”后的内容更像待处理工作流，而不是普通列表。

改动方向：

1. 最近活动分为三个轻量区块：待审查、今日候选、已入档。
2. 每条活动显示四个字段：状态、标题、影响范围、下一动作。
3. 今日候选标题改成中文可读摘要，例如“更新前端交互与证据链路”，避免直接显示英文 commit 或 `WORKTREE`。
4. 右侧动作只保留一个主按钮：审查、生成候选、查看。

验收：

1. 用户扫一眼能知道当前最该处理的是哪一条。
2. 英文技术字段不直接作为主标题。
3. 同一条记录不在同屏重复出现两次。

## 阶段 2：入口去重规则

目标：减少“看起来很多入口，实际去同一页”的冗余。

保留入口：

1. 首页顶部：项目选择、添加项目、上手流程、模型状态、删除项目。
2. 首页统计卡：只作为当前页筛选入口，不跳到其他页。
3. 右侧架构入口：只进入项目架构详情。
4. 最近活动：只进入当前记录对应动作。

删除或降级：

1. 已在首页统计区展示的数据，不再在旁边重复展示同一计数。
2. 已有“去变更审查”的主入口时，其他卡片只显示状态，不再重复放同样按钮。
3. 架构条目数只在架构入口展示，其他区域不重复。

验收：

1. 同一页面同一目标最多保留一个强入口。
2. 辅助入口必须解释“为什么此处也需要进入”，否则删除。

## 阶段 3：按钮与信息气泡规范

目标：让用户能准确区分“能点”和“只是状态”。

按钮：

1. 用于触发请求、页面跳转、打开弹窗。
2. 必须有 hover 变色、轻微位移或阴影增强。
3. 禁用按钮必须有 `title` 解释原因。

信息气泡：

1. 用于展示模型名、项目状态、条目数、来源状态。
2. 不使用按钮高度和强边框。
3. 不显示箭头，不显示手型光标。

验收：

1. 页面上所有看起来像按钮的元素都能点击。
2. 不能点击的元素视觉上更像标签或状态。

## 阶段 4：每日回顾来源去模板化

目标：每日回顾来源只展示可判断的事实，不展示长模板正文。

改动方向：

1. 改成来源卡片：今日日志、项目演进、任务状态、证据包、风险决策。
2. 有内容显示数量和最近摘要。
3. 无内容显示“无”，不展开空模板。
4. 点击卡片再看详情，不在首页长段铺开。

验收：

1. 没有来源时，用户看到的是清晰的“无”，不是一段模板空话。
2. 有来源时，用户能知道它来自哪类数据。

## 阶段 5：独立上手验收

用新用户视角验证完整流程：

1. 首次进入：能找到添加项目入口。
2. 导入后：能看到项目画像和架构入口。
3. 绑定路径后：能理解为什么要刷新变化。
4. 开发后刷新：能看到具体变化候选。
5. 生成证据包后：能继续生成候选变更，不出现请求失败。
6. 审查采纳后：能看到项目档案和成长记录确实更新。
7. 生成输出时：能看到输出用了哪些已确认来源。

最终验收标准：

一个新用户不读文档、不依赖 Agent 配合，也能完整走通这条链路。
