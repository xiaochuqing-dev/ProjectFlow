# ProjectFlow V2 Refresh Stability Final Report

Date: 2026-06-07

## 本轮目标

这轮主要处理用户实测时发现的 V2 可用性问题：

- 导入大项目 zip 后，切到个人设置或成果输出，再回到项目管理时，项目档案 / 初始分析会消失。
- 页面刷新后也需要保留已导入项目的关键画像，不应只依赖本次上传返回值。
- 成功 / 错误提示气泡会一直停留，需要自动淡出。
- DeepSeek 的 Max Tokens 上限太低。
- 重复写入 `.projectflow` 协议时，提示语要区分首次接入和已接入后的刷新。
- 多次重复导入后产生的重复待确认建议，需要能删除或忽略。

## 已完成修复

### 1. 项目档案不再只依赖本次上传状态

项目管理页现在会优先使用本次 zip 导入返回的 `projectProfile`。

如果用户切换页面、回到项目管理，或者刷新页面导致本次上传状态丢失，前端会从已保存的项目材料、项目本身信息、待确认建议中重建一个可展示的项目画像。

这样可以覆盖下面两种情况：

- 从个人设置 / 成果输出返回项目管理页。
- 浏览器刷新 `/dashboard` 后重新加载项目上下文。

### 2. 提示气泡自动淡出

项目管理页和个人设置页的成功 / 错误提示现在会在约 4.2 秒后自动清空。

这解决了提示一直悬浮在页面底部的问题。

### 3. 待确认建议支持忽略

待确认建议列表新增了两种清理方式：

- 单条建议右侧可以点击删除图标，将该建议标记为 `IGNORED`。
- 顶部可以点击 `忽略选中 N`，批量忽略已勾选的建议。

这不会删除历史数据，只会把建议从待处理队列里移走，适合清理重复导入产生的重复建议。

### 4. 重复写入协议时使用更合理提示

后端现在会返回 `alreadyLinked`。

前端会根据这个字段区分提示：

- 第一次写入：提示已完成首次接入，并写入 `.projectflow` 文件。
- 后续重复写入：提示项目已接入 ProjectFlow，本次只是刷新协议文件和上下文。

这样用户不会误以为之前没有写入成功。

### 5. DeepSeek Max Tokens 上限提高

AI Provider 的 `maxTokens` 后端校验上限已从 `200000` 提高到 `5000000`。

个人设置页面输入框也同步提高到 `5000000`。

说明：这个值是 ProjectFlow 允许保存的配置上限，实际能否使用这么长的上下文，仍然取决于 DeepSeek 或 OpenAI-compatible 服务本身的模型限制。

### 6. DeepSeek Base URL 容错仍然保留

如果用户把 DeepSeek Base URL 填成完整接口：

```text
https://api.deepseek.com/chat/completions
```

后端会自动归一化为：

```text
https://api.deepseek.com
```

当前推荐用户在设置页直接填写：

```text
https://api.deepseek.com
```

## 用户最终测试建议

建议按下面顺序做一次人工测试：

1. 重启 ProjectFlow，确保浏览器加载的是新代码。
2. 进入个人设置，确认 DeepSeek 配置已存在，Max Tokens 可以设置到较大值。
3. 回到项目管理，导入一个完整项目 zip。
4. 确认项目档案 / 初始分析正常显示。
5. 切到个人设置，再切回项目管理，确认项目档案仍然显示。
6. 切到成果输出，再切回项目管理，确认项目档案仍然显示。
7. 直接刷新 `/dashboard`，确认项目档案仍然可以从已保存材料恢复。
8. 观察成功 / 错误提示，确认 3 到 5 秒内会自动消失。
9. 对重复建议使用单条删除图标或 `忽略选中 N`，确认重复建议能从待确认列表移走。
10. 点击 `写入协议` 两次，确认第二次提示是已接入后的刷新，而不是让用户误会之前没有写入。

## 仍需注意

如果项目 zip 仍然过大，虽然后端上传上限已提高到 512MB，但仍建议不要把下面内容打进 zip：

- `node_modules`
- `.git`
- `dist`
- `.next`
- `build`
- `logs`
- 大型二进制资源
- 私密 `.env`

ProjectFlow 的定位是读取项目结构和关键资料，不是备份整个工程目录。

## V3 展望

V3 不建议变成商城式、酒店后台式或大卡片宣传式产品。

更合理的方向是继续保持开发者工具取向：

- 桌面端或本地 helper：解决文件夹选择、路径权限、`.projectflow` 文件监听、本地服务启动这些 Web 端天然不方便的问题。
- 自动监听 agent 结果：发现 `.projectflow/inbox/` 或任务 result 更新后，自动提示用户确认。
- Review 式确认面板：把 agent 写回内容拆成事实、任务变化、风险、决策、开发日志，让用户逐条采纳或忽略。
- 更强的去重能力：对重复 zip 导入、重复 agent result、相似任务建议做自动合并或提示。
- Agent 记忆接入：继续保留文件协议作为低成本方案，同时后续可以增加 MCP / API 读取 ProjectFlow 上下文。

桌面端成本判断：中等，不是重写产品，但也不是小修小补。前端页面、后端 API、`.projectflow` 协议都可以复用；主要成本在本地文件权限、安装包、自动更新、跨系统兼容、后台服务管理和故障诊断。低成本路线是先做 Tauri helper，只负责选择文件夹、监听 `.projectflow`、启动或连接本地服务，而不是一开始重做成大型桌面客户端。
