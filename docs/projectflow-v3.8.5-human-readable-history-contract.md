# V3.8.5 大众可读项目历程合同

默认第一层

第一层按 Overview → Chapter → Story → Thread 展示“做了什么、原来怎样、改变了什么、得到什么结果、后来怎样”。标题和摘要优先使用中文动作、可识别对象和用户/项目结果。工程师仍可进入 Raw Event → Evidence 查看 Commit、相对路径、代码范围、测试和当前性。

Story 必须具备

- `Before`：只描述已覆盖来源能确认的此前状态。
- `Change`：描述一次完整工作成果，而不是文件列表。
- `After`：描述该时间点可确认的结果。
- `role`：`PRIMARY` 是主要成果，`SUPPORTING` 是测试、文档、配置或验证支撑。
- `eventRefs`、`evidenceRefs`：始终可下钻且不因压缩丢失。
- `reason`：只有 eligible Evidence 支持时才填写，否则保留未知。

首层禁止

禁止以 SHA、Evidence ID、绝对路径、目录名、类名后缀、内部枚举、文件扩展名堆叠、文件数统计、“工程分组”“相关变化”“形成初始结果”等作为主标题或摘要。OAuth、PDF、Markdown、API、Docker 等用户可识别产品/格式名可以保留，但必须配合清晰结果。

不确定性

未知、冲突、覆盖范围和未处理窗口必须显示为限制，不得被“优化”“已成功”“成熟阶段”“下一步”之类的模型措辞覆盖。用户声明只能改变展示，不改变事实、事件、Evidence 或强事实状态。
